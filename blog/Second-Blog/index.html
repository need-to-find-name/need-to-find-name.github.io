添加了可视化blog编写页面，带有一键发布/预览文章等功能

这个博客底层用的是 gitfolio。它是一个把 GitHub 账号渲染成静态网站的小工具，能显示个人资料和公开仓库，也带一个写博客的界面。问题是它上游已经在 2022 年 2 月归档、不再维护了，而且写文章那一套流程一直是「手敲命令 + 网页表单」的组合。

过去写一篇文章，我要打开终端、cd 到项目目录、敲一条生成命令、等浏览器打开表单、填标题和副标题、上传图片、点提交。每一步都不难，但每次都要重来一遍，中间还有好几个会静默失败的地方。

这两天我把它从「能跑」改成「顺手」，记录一下到底改了什么。

原来的流程是什么样

gitfolio 的工作方式其实很简单，一句话：它把 GitHub 账号渲染成一个静态网站。

  • 首页的姓名、简介、头像、所在地，全部来自 GitHub API 返回的账号资料
  • 首页的 Work. 区块就是公开仓库列表，一个仓库一张卡片
  • 生成结果统一放在 dist/ 目录，推到 need-to-find-name.github.io 仓库后由 GitHub Pages 托管

所以它有两处数据源 —— GitHub 账号和本地文章 —— 而 dist/ 只是一张快照。GitHub 上改了资料或加了仓库，不重新生成一次，线上什么都不会变。

原来写一篇文章要过几道坎

这些都是真实踩出来的，不是假设：

环节 原来的问题
打开编辑器 得手动 cd 到项目目录再敲命令，命令记不住
写正文 网页编辑器的正文字段只在键盘敲击时同步，粘贴进去的内容不会被提交
上传图片 顶部大图是必填项，漏传时报错不明显
提交失败 正文为空时服务端只返回一行文字，终端里什么都不打印，很容易以为「点了没反应」
本地预览 编辑器 ui 和预览 run 都默认占用 3000 端口，同时开必然有一个崩
更新站点 改完 GitHub 资料或仓库后忘了重新生成，推上去的还是旧快照，首页区块是空的
发布 手动三步：复制 dist/ 内容到发布仓库、git add 和 commit、git push
文章网址 目录名由标题生成，标题里的中文会被过滤掉，纯中文标题会变成空目录名
大小写 Windows 不区分大小写，GitHub Pages 跑在 Linux 上区分，本地正常、线上一开就是 404

现在改成什么样

核心原则是一个渲染器、一个发布器：所有入口最终都走同一条链路，避免「界面里是对的、命令行里是错的」。

三个入口各管一段：

  • BlogStudio —— 双击就能打开的图形界面，主要用来写文章
  • blog 命令 —— 命令行方式，blog new、blog list、blog publish
  • 发布脚本 —— 只管发布，不写文章

链路是固定的：写 Markdown，渲染成 HTML，校验，同步到发布仓库，提交推送。

逐项对比

环节 原来的做法 现在的做法
打开编辑器 手动切目录加敲命令 双击一个程序，浏览器自动打开
写正文 网页富文本，粘贴会丢 直接写 Markdown，支持标题、列表、引用、代码块、表格
图片 顶部大图必填且容易漏 选图即上传，自动落到文章目录，重名自动加序号
预览 要另起一个服务，还会抢端口 保存后右侧直接刷新预览
发布 复制加三条 git 命令 一个按钮
更新站点信息 记得重新跑生成命令 一个按钮，重新拉取资料和仓库再发布
出错时 只回一行文字，终端没有输出 完整输出打到界面的日志区
中文 标题中文会生成空目录名 标题、副标题、正文、图片名全链路支持中文

顺手加的几道自动检查

原来很多坑的共同点是「不出声」，所以我加了几道会在发布前拦下来的检查：

  1. 博客目录大小写一致性 —— 不一致就直接报错。线上是 Linux，大小写不一致会 404，但本地完全看不出来
  2. 快照是否真的重新生成 —— 比对生成产物的时间戳，没变就中止，避免把旧内容推上线
  3. 删除残留检测 —— 复制文件的操作只增不删，删过的文章会一直留在线上，现在会列出来提醒
  4. 旧文章自动备份 —— 把早期 HTML 格式的文章转成 Markdown 时，原文件先备份成 .bak

现在还做不到的

把边界说清楚，避免误导：

  • 正文是「点保存后刷新预览」，没有逐字实时预览
  • 正文里的原始 HTML 会被转义成文本，只能用 Markdown 语法
  • Markdown 支持的是常用子集：标题、段落、粗体斜体、行内代码、代码块、有序和无序列表、引用、分隔线、图片、链接、表格。任务列表、删除线、脚注、表格里的合并单元格都没做

一点实现上的收获

真正花时间的其实不是功能本身，而是几个环境细节：

  • Node 调用 PowerShell 时的中文乱码 —— 子进程默认按系统代码页输出，得先让 PowerShell 把输出编码设成 UTF-8
  • Windows 批处理文件必须用 CRLF 换行 —— 用 LF 写出来的 .cmd 双击后报了一串「不是内部或外部命令」，因为解析器把命令行拆错了位置
  • PowerShell 脚本文件必须带 UTF-8 BOM —— 否则中文注释会被按本地代码页解析，抛出莫名其妙的括号语法错误

这些东西文档里不会写，只有真跑一遍才会遇到。
