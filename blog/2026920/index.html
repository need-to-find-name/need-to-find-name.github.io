2026.9.20个人博客更新汇总

借助workbuddy实现的gitfolio个人博客的升级

这个博客底层用的是 gitfolio —— 一个把 GitHub 账号渲染成静态网站的小工具。我最初 clone 下来的时候，它已经归档四年了（最后一次提交是 2022 年 2 月），能跑，但用起来很费劲。这两天我把它从「能跑」改成了「顺手」，记一下都改了什么。

起点：clone 下来的是什么

上游仓库一共 31 个文件，能力就两件事：

  • 首页：把 GitHub 账号资料和公开仓库列表渲染成个人主页
  • 博客：一个网页表单，填标题、传图、写正文，然后生成静态页面

用它也不轻松：命令行切目录、敲生成命令、开浏览器、填表单、点提交，最后再手动复制产物、git 提交、git 推送。中间有好几个会静默失败的地方。

现在多了什么

写文章换成了 Markdown。 原来那个网页表单只在键盘敲击时同步正文，粘贴进去的内容不会被提交；顶部大图必填；内容为空时还不报错。现在直接写 Markdown，标题、列表、引用、代码块、图片、链接都能用。

两种写法，同一套底层。一个是可以双击打开的图形界面，一个是命令行。不管走哪条路，渲染和发布的逻辑都是同一套，不会出现两边结果不一样。

一键上线。原来是「复制产物 → 三条 git 命令」三步手动操作，现在点一次按钮或者敲一条命令就完事。

实时预览。右边边写边显示渲染结果，不用先保存再看效果。

Markdown 能力补齐。 除了常规语法，还支持表格（含左中右对齐）、任务列表、删除线、脚注，以及合并单元格。文章页的排版也顺手补齐了 —— 原来只有段落和图片有样式，标题、代码块、引用、列表全是浏览器默认的样子。

一批自动检查。 都是我在用的时候真踩过的坑：

  • 文章目录大小写不一致，本地正常但线上会 404 → 发布前直接拦下来
  • 改了 GitHub 资料或仓库却忘了重新生成，推上去还是旧内容 → 比对文件时间戳，没生成就中止
  • 复制文件只增不删，删掉的文章会一直留在线上 → 发布前列出来提醒
  • 早期 HTML 格式的文章转成 Markdown 时，原文件先自动备份

发布后能马上看到。&#8203; 之前新文章最多要等十分钟才出现在首页，是缓存的问题，现在绕过了。

对比

环节 原来 现在
打开编辑器 手动切目录 + 敲命令 双击一个程序
写正文 网页富文本，粘贴会丢 写 Markdown
预览 要另起一个服务，还会抢端口 边写边见
图片 顶部大图必填且容易漏 选图即上传
发布 复制 + 三条 git 命令 一个按钮
出错时 终端没有输出 完整输出打到界面日志里
中文 标题中文会生成空目录名 标题、正文、图片名全支持中文

规模上，一共新增 11 个文件（2 个是全局命令入口），新加的部分没有引入任何第三方依赖，用的都是 Node 和 PowerShell 自带的能力。
